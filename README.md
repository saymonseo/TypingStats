# TypingStats 0.3.0

Персональный счётчик клавиатурного ввода для Windows. Это рабочая первая версия с ограничениями точности, а не завершённая универсальная реализация всех сценариев исходного ТЗ.

Репозиторий: https://github.com/saymonseo/TypingStats

Готовые сборки: https://github.com/saymonseo/TypingStats/releases

Полное проектное ТЗ: [docs/spec.md](docs/spec.md). Фактические ограничения и проверки: [docs/compatibility-report.md](docs/compatibility-report.md) и [docs/verification-report.md](docs/verification-report.md).

Версия 0.1.1 обновляет интерфейс: боковая навигация, современные карточки, таблицы и переключатели настроек. У программы теперь собственная иконка в трее, окнах и executable; жёлтый значок обозначает паузу, красный — ошибку сохранения. Данные и правила подсчёта остаются совместимыми с 0.1.0.

## Подробная статистика 0.3.0

Страница **Статистика** показывает ежедневные суммы и клавиши каждого выбранного дня. Период задаётся сверху: сегодня, вчера, 7/30 дней, всё время или произвольные даты. Фильтры: приложение, группа клавиш и поиск (W, Ctrl, русская буква или «пробел»). Сводка и обе таблицы учитывают одни и те же фильтры. «Дни без записей» показывает пропуски; отсутствие записей не доказывает, что в этот день компьютер не использовался.

Слева выберите день — справа появятся его клавиши, число нажатий, доля, повторы и приложения. «Все дни» возвращает суммарный вид. **Экспорт периода** выгружает весь выбранный диапазон независимо от выделенного дня; **Экспорт дня** — только этот день. Форматы UTF-8 CSV: подробные записи день/приложение/клавиша, сводка по дням, суммы по клавишам. Название программы и EXE включаются в подробный CSV отдельно.

Процесс определяется по PID окна ввода в момент события, а имя — по метаданным его EXE. Заголовки документов и адреса сайтов не используются. PID, путь executable и последовательность клавиш в историю не записываются; локальный fingerprint пути различает копии одинаково названных EXE. Если процесс завершился, PID переиспользован или доступ ограничен, приложение не приписывает событие текущему окну и может показать неизвестный процесс. Хосты вроде Java/терминалов могут обозначать именно процесс-хост, а не вложенную программу. Старые записи сохраняют прежнюю привязку к EXE.

## Обновления через GitHub

Откройте **Обновления → Проверить**. Программа читает публичные GitHub Releases без токенов; сеть используется по этой команде. Предварительные версии включены по умолчанию, поскольку текущие сборки проекта — preview. ZIP скачивается с релиза, проверяется по SHA-256 от GitHub и распаковывается в локальный staging-каталог.

После подтверждения программа ставит сбор на паузу, сохраняет историю и создаёт копию базы. Отдельный `TypingStats.Updater.exe` ждёт завершения старого процесса, заменяет только программные файлы в прежней папке и запускает новую версию. Новая версия подтверждает успешное начало работы. При неудачной замене или отсутствии подтверждения восстанавливаются прежние программные файлы; копия базы используется при откате после неудачного старта. Состояние обновления сохраняется локально в папке updates.

При обычном режиме база и настройки остаются в `%LOCALAPPDATA%\TypingStats`, при portable — в существующей `data`. Маркер portable.flag и пользовательские данные пакет не заменяет. Автозапуск указывает на тот же EXE-путь. Установка в каталог без права записи потребует сначала перенести **программу** в доступную папку; приложение не повышает права автоматически.

Чтобы впервые получить механизм OTA, версию 0.3.0 нужно установить один раз вручную: 0.2.0 ещё не содержит эту кнопку. Историю переносить при обычном запуске не требуется. Последующие версии устанавливаются из окна обновлений. Историю и конфигурацию нельзя включать в ZIP релиза.

Для нашей публичной схемы не требуется отдельный сервер или платный GitHub-план. Работает обычный GitHub Free/Releases; действуют ограничения API по частоте запросов. SHA-256 подтверждает совпадение с опубликованным файлом, а не заменяет цифровую подпись издателя.

## Режимы учёта 0.2.0

Режим выбирается в верхней панели или настройках:

| Режим | Что учитывается |
| --- | --- |
| Текст | Прежние показатели символов и исправлений; новые частоты клавиш не сохраняются |
| Все нажатия | Клавиатурные keydown-события во всех доступных приложениях, включая игры; перевод клавиш в текст отключён |
| Текст + клавиши | Обе независимые статистики одновременно; режим по умолчанию |

Чтобы смотреть игры, выберите **Все нажатия** и откройте страницу **Клавиши**. Она показывает карту основного блока, таблицу всех использованных клавиш (включая Numpad и мультимедийные), суммы, долю и автоповторы. Левые/правые Ctrl, Shift, Alt и основной/цифровой Enter разделяются. Счётчики основаны на scan code и extended flag; нестандартные клавиши отображаются отдельными кодами. Карта — условная PC-схема, а не определение модели подключённой клавиатуры.

В настройках доступны «Автоповтор считать отдельными нажатиями» и «Учитывать программные / injected-нажатия». Автоповтор включён по умолчанию; его отключение считает начало удержания как одно нажатие. Опция влияет на статистику клавиш, а символы текста продолжают считаться по результату/оценке ввода. Программные нажатия изначально выключены. Unicode-пакеты программного ввода объединяются в общую группу без сохранения их character-valued scan codes.

Настройки применяются к дальнейшему сбору; ранее сохранённая история автоматически не пересчитывается.

В режиме клавиш Ctrl+V — нажатия Ctrl и V, но не длина вставленного текста. Backspace увеличивает счётчик нажатий и не уменьшает его. Скорость, активное время, график, тепловая карта и дневная цель переключаются на показатели нажатий. В текстовом режиме действуют ограничения точности прежнего счётчика: обычный keydown не доказывает, что символ действительно появился в документе.

Экспорт CSV со страницы «Клавиши» выгружает частоты; на остальных страницах — обычные агрегаты с дополнительными колонками нажатий. Частоты хранятся по дням и приложениям; порядок и точное время отдельных нажатий не записываются. История по клавишам начинается после обновления и не восстанавливается из старых суммарных показателей.

Версия базы — 2. При переходе с версии 1 автоматически создаётся `before-schema-2-*.sqlite`, а старая история текста сохраняется. Старые версии программы не читают схему 2; для отката используйте сохранённую копию.

Учёт ведётся на рабочем столе текущего пользователя. Совместимость с каждой конкретной игрой не проверена: защищённые/повышенные процессы, античит или драйвер могут ограничивать получение событий. Программа не обходит такие ограничения. В режиме клавиш сбор не зависит от UI Automation/наличия текстового поля.

## Запуск

1. Распакуйте `TypingStats-win-x64.zip` целиком в отдельную папку.
2. Запустите `TypingStats.exe`. Не вынимайте один executable из папки: ему нужны соседние DLL.
3. Откройте статистику из системного трея. Крестик окна скрывает окно; команда «Выход» завершает сбор и сохраняет данные.
4. Пауза: Ctrl+Alt+F12. В настройках можно выбрать другую F-клавишу. Если сочетание занято, используйте меню трея.

Нужна Windows x64 и .NET Desktop Runtime 10. На компьютере, где проводилась сборка, этот runtime уже установлен. Установщик и административные права не требуются.

Автозапуск изначально выключен. Включить его можно в настройках; это единственная штатная функция, добавляющая запись в пользовательский Windows Run key.

## Где находятся данные

По умолчанию: `%LOCALAPPDATA%\TypingStats\stats.sqlite` и `settings.json`.

Для хранения рядом с программой создайте пустой файл `portable.flag` в папке executable до запуска. Программа будет использовать подпапку `data`. Папка должна быть доступна для записи. Перенос существующей базы между режимами выполняется через backup/restore, автоматически базы не смешиваются.

По умолчанию сохраняются минуты за 90 дней, часы за 2 года и дни бессрочно. При открытии старой истории применяется дневная детализация. Резервные копии создаются в `backups`; доступны команды ручной копии и восстановления. Перед полным удалением истории или восстановлением автоматически сохраняется текущая база.

## Что уже работает

- Глобальный захват клавиатуры, трей, один обычный экземпляр на пользовательскую сессию.
- Unicode-графемы и обычные раскладки, модификаторы и автоповтор.
- Раздельные числовые показатели: оценено по клавишам и получено из результата композиции.
- Оценка после связанных Backspace; вставка и навигация прекращают связь с предыдущим набором.
- Игнорирование Ctrl+V/Shift+Insert для объёма текста; clipboard не читается.
- Привязка к executable, поиск и сортировка таблицы приложений, ручные категории через двойной щелчок.
- История, почасовой график, тепловая карта, раскладки, завершённые сессии и активное время.
- SQLite с транзакциями, числовыми агрегатами, защитой от повторного применения batch, backup/restore и CSV.
- Сохранение каждые 5 секунд. Несохранённые агрегаты сохраняются в recovery-файл при штатном выходе после ошибки БД.
- Ручная пауза, настройка горячей клавиши, автозапуск, дневная цель и уведомление.
- UI Automation COM: подписка на активное поле и события Composition/CompositionFinalized на отдельном MTA-потоке.

## Как понимать показатели

**Напечатано** = число графем из наблюдённых композиционных результатов + оценка по физическим клавишам. Вклад обычной клавиатуры всегда является оценкой: клавишу может перехватить игра, терминал или командный режим редактора.

**После правок ≈** = накопленный объём минус связанные одиночные Backspace в непрерывной серии. Это не размер оставшегося документа. Delete, удаление слова, Undo/Redo, Cut, удаление после вставки или навигации не вычитают неизвестную длину.

Пример: `abc → Backspace` даёт gross=3, net≈2. `abc → Ctrl+V → Backspace` даёт gross=3, net≈3: последнее удаление могло относиться к вставленному тексту.

За отдельный период net может быть отрицательным: в этот период удалено набранное ранее. Отрицательные минутные/часовые дельты не обрезаются, чтобы суммы оставались согласованными. График рисует только положительную часть оценки; полные значения доступны в таблице/CSV.

**Активное время** — объединение коротких интервалов после текстового вклада, по умолчанию 5 секунд. **Скорость** = объём / активные минуты; до 30 секунд активности она показывается как «мало данных». Эти показатели не измеряют продуктивность и число ошибок.

## Ограничения версии 0.1

- Нет обещания точного учёта любого текста в любом приложении. Матрица реальных приложений и IME ещё не проверена.
- Обычный ввод считается по клавиатуре; режим редактора и факт изменения документа не подтверждаются.
- Enter и Tab пока не прибавляются к тексту, поскольку их назначение зависит от поля.
- Dead keys отмечаются как неизвестные; полноценная композиция диакритики через keyboard-layout adapter требует дальнейшей проверки.
- IME-адаптер принимает результат только при установленном контексте, предшествующих клавиатурных событиях и событиях Composition + Finalized. Смена фокуса или неподдерживаемый провайдер может дать неизвестный результат.
- Emoji-панель, сенсорная/экранная клавиатура и другие injected-источники пока не заявлены как поддержанные. Неоднозначные injected-события не прибавляются к тексту.
- Раскладка — не определённый язык текста. Браузеры учитываются целиком, без сайтов и вкладок.
- Нет обхода защищённых полей, экранов блокировки и ограничений доступа к повышенным приложениям.
- В первой версии нет проектных меток, распределения скорости/P90, семидневного среднего, рекордов, индивидуальных профилей совместимости и удаления части истории через интерфейс. Удаление всей истории доступно с backup.
- Проверены ядро, хранение, запуск и отрисовка. Проверка реальных физических клавиш в сторонних программах, живых IME и 8-часовой soak-тест пока не выполнены.

Приложение хранит только агрегаты. Коды клавиш временно проходят через ограниченную очередь в памяти, а короткий Unicode-хвост нужен для границ графем; постоянной истории клавиш нет. Текст, clipboard, названия документов, адреса сайтов и заголовки окон не записываются. Системные строки в памяти невозможно обещать мгновенно стереть.

## Проверки и сборка

Из папки исходников, с .NET SDK 10:

```powershell
dotnet restore App/TypingStats.App.csproj
dotnet build App/TypingStats.App.csproj -c Release
dotnet run --project Tests/TypingStats.Tests.csproj -c Release
```

Тесты — отдельный console runner, exit code 0 означает успешное прохождение. Он проверяет независимо заданные Unicode-примеры, разные границы фрагментов, удаления, периоды, активное время и SQLite backup/restore/idempotence.

Поставка собирается командой `./build.ps1`. Скрипт не запускает установку или автозапуск.

Иконки уже находятся в `App/Assets`. Чтобы воспроизвести их из геометрического рисунка: `dotnet run --project Tools/IconBuilder/IconBuilder.csproj -- App/Assets`.

## Контрольное поле и диагностика

`TypingStats.exe --test-host` открывает отдельное поле для ручной проверки. Текст в нём существует только в памяти. Его длина включает вставки и нужна как контрольная величина, а не как замена глобальному счётчику.

`--data-dir <папка>` выбирает отдельную базу. Не используйте рабочую историю для диагностики.

`--verify --data-dir <новая пустая папка>` проверяет внутренний конвейер на заранее заданных метаданных без отправки клавиш другим приложениям, сохраняет числовой report и снимки собственных вкладок, затем завершает приложение. Это не тест физической клавиатуры или реального IME.

`--smoke --data-dir <папка>` проверяет запуск, hook, UIA, горячую клавишу и отрисовку, затем выходит.

`--benchmark --data-dir <папка>` измеряет 30 секунд фонового простоя после 5-секундного прогрева и создаёт `benchmark-report.json`. Это короткая проверка, не полный benchmark из ТЗ.
