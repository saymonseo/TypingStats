# Техническое задание: персональный счётчик набранного текста для Windows

Версия: 1.0. Дата: 29 сентября 2026 года. Рабочее название: TypingStats.

Документ определяет продукт, правила подсчёта, архитектуру, данные и критерии приёмки. Это задание на разработку; описанные проверки ещё не проведены. Совместимость конкретных приложений должна быть установлена экспериментально на первом этапе.

## 1. Назначение и согласованные требования

Создать небольшую локальную Windows-утилиту для личного использования. Она работает в фоне и показывает объём текста, который пользователь вводит с клавиатуры, динамику этого объёма и распределение по приложениям.

Согласовано с пользователем:

- Два основных показателя: всего напечатано и оценка объёма после исправлений.
- Вставленный текст, в том числе через Ctrl+V, не увеличивает объём напечатанного.
- Нужна разбивка по приложениям.
- Требуется ввод независимо от языка, раскладки и вида символов, включая IME и составной Unicode.
- Используется гибрид: глобальные клавиатурные события и доступные события завершения композиции UI Automation.
- Сохраняются агрегаты; текст, содержимое буфера обмена, заголовки окон, документы и адреса сайтов не сохраняются.
- Пользователь не запрашивает исключения по приложениям или парольным полям. Специальных списков исключений в версии 1.0 нет.
- Приложение предназначено для своего компьютера; сервер, аккаунт и сетевые функции не нужны.

Область наблюдения: интерактивный рабочий стол текущего пользователя. Ввод на экране блокировки, защищённом рабочем столе, в другой пользовательской сессии и внутри удалённого компьютера не входит в гарантии. Для удалённого клиента локальные нажатия могут относиться к executable клиента, но содержимое удалённого редактора не определяется.

## 2. Границы точности

Требование «любые символы» задаёт цель покрытия способов ввода, а не обещание точности в каждом существующем приложении. Keyboard hook сообщает о клавише до обработки приложением. UI Automation сообщает итог композиции только при поддержке нужного pattern провайдером поля.

Продукт обязан различать:

| Класс количества | Значение | Как показывать |
| --- | --- | --- |
| ResultObserved | Получен конечный текстовый результат от проверенного адаптера; происхождение ввода соответствует принятому сценарию | «По результату ввода» |
| KeyEstimated | Количество оценено по клавишам, состоянию раскладки и доступному контексту | «Оценено по клавишам» |
| Unresolved | События ввода обнаружены, но количество итоговых символов не установлено | «Есть неучтённый ввод» |

ResultObserved не является универсальной гарантией, что изменился документ: это описание источника измерения. Обычный keyboard hook сам по себе никогда не получает этот класс.

Дополнительно хранить признак происхождения: keyboard_correlated, interactive_software_keyboard, ambiguous. Последний не включать в счётчик текста автоматически. Временная близость событий сама по себе не доказывает ручное происхождение.

Основной показатель: gross_total = gross_observed + gross_estimated. В интерфейсе и CSV всегда доступны обе составляющие. Число неизвестных событий не переводить в предполагаемое число символов и не использовать как знаменатель «процента точности».

Точность удаления — независимый признак. Даже событие с известной длиной вставленного результата не доказывает, что последующий Backspace удалил именно этот результат.

## 3. Определение символа

Единица текстового объёма — расширенная графема Unicode, то есть один воспринимаемый пользователем текстовый элемент. Использовать StringInfo либо эквивалентную проверенную реализацию правил Unicode из выбранного runtime.

Примеры: буква А — 1; 中 — 1; é — 1; e с комбинируемым акцентом — 1; составной emoji 👩🏽‍🚒 — 1. Длина string в UTF-16 и количество Rune не подходят для основного показателя.

Политика пробельных и управляющих символов:

- Пробел, неразрывный пробел и другие введённые пробельные графемы: +1; отдельно в категории whitespace.
- Перевод строки: +1 только в проверенном сценарии вставки строки; CRLF нормализовать в одну единицу. Enter как отправка сообщения, выбор кандидата IME или команда не увеличивает объём.
- Tab: +1 только когда установлен сценарий вставки табуляции. Переход между полями и запуск автодополнения не увеличивают объём. Разворачивание Tab в несколько пробелов редактором не приписывать пользователю без адаптера.
- Escape, стрелки, функциональные клавиши, модификаторы и команды: 0 символов.
- Невидимые компоненты графем, например ZWJ, не считать отдельно от графемы; одиночные нестандартные управляющие последовательности помечать как неоднозначные.
- Голосовой ввод, макросы, автозаполнение, автокоррекция и программные вставки не прибавляют объём ручного набора.

Автоповтор учитывается: каждый повтор keydown, соответствующий вводу, создаёт вклад в оценку символов. Отдельно хранить количество повторов. Первичный keydown и повтор различать собственным состоянием keydown/keyup; не считать keyup вторым нажатием.

Раскладка не равна языку текста: английская раскладка может использоваться для программного кода, русского транслита и многих языков. В отчётах использовать название «раскладка / профиль ввода», а не «язык текста».

## 4. Правила клавиатурных сочетаний и вставок

Ctrl+V и Shift+Insert не увеличивают текстовые показатели. Содержимое clipboard не читать даже для определения длины. Ctrl+C, Ctrl+X, Ctrl+A, Ctrl+Z, Ctrl+Y, Win-сочетания и другие команды не транслировать в обычные буквы.

AltGr распознавать отдельно от обычного Ctrl+Alt. Не запрещать все сочетания с Ctrl без исключения AltGr. Dead keys, переключения раскладки и Alt+numpad должны иметь отдельные сценарии проверки.

Прямой обработчик вставки не нужен: событие обычного изменения текста не является основанием прибавить его длину. Меню «Вставить», перетаскивание текста и история clipboard не увеличивают объём через общий TextChanged. Обнаруженное изменение такого рода прерывает связь с текущей серией для расчёта удалений.

Если нестандартный провайдер представляет вставку как композицию, адаптер должен пройти тесты происхождения. При неразличимости ручного результата и вставки такой сценарий переводится в Unresolved, а не включается в ResultObserved.

Флаг injected не позволяет отличить все макросы от экранной клавиатуры. По умолчанию неподтверждённые injected-нажатия не входят в ручной текст. Проверенная экранная клавиатура получает отдельный адаптер. Число событий без установленного происхождения отображается в диагностике качества.

## 5. Оценка объёма после исправлений

Название в интерфейсе: «После исправлений ≈». Подсказка: «Оценка набранного объёма с вычетом связанных Backspace. Не равна длине документа; часть удалений не удаётся связать с набором».

Три показателя:

1. gross_total — накопленное число введённых графем по двум допустимым классам.
2. linked_backspace_estimate — количество вероятных одиночных удалений, связанных с текущей серией набора.
3. net_estimate = gross_total − linked_backspace_estimate.

Под серией понимается непрерывный набор в одном контексте поля без известного перемещения курсора, выделения, вставки и неизвестных изменений. Отсутствие надёжного идентификатора поля снижает качество связи; такая серия помечается context_estimated.

Обычный Backspace уменьшает остаток серии максимум на 1, если в серии есть ненулевой остаток, нет активной IME-композиции и не было прерывающего действия. При этом событие всё равно является оценкой: приложение может перехватить клавишу или удалить часть составного символа.

Backspace при редактировании ещё не завершённой IME-композиции не уменьшает уже накопленный текст. При невозможности определить принадлежность удаления учитывать только действие.

Обычный Delete фиксируется отдельно без автоматического вычитания: символ справа от курсора может принадлежать ранее существовавшему тексту. Ctrl+Backspace, Ctrl+Delete, удаление выделения, Cut и Undo/Redo также учитывать как действия без выдуманного размера.

Связь серии прекращается при:

- Смене приложения или наблюдаемого поля.
- Навигации курсором, выделении, вставке, Cut, Undo/Redo.
- Enter или Tab, если дальнейшее положение курсора неизвестно.
- Наблюдаемом перемещении выделения/каретки или щелчке мыши, способном изменить позицию.
- Неподдерживаемом изменении текста, потере очереди, смене источника без надёжной корреляции.
- Пауза учёта, блокировка, сон, выход пользователя, перезапуск.
- Отсутствии текстового ввода более 60 секунд.

Щелчки можно наблюдать минимальным обработчиком button-down, без хранения координат; мышь не включается в клавиатурную статистику. Ненаблюдаемые изменения остаются ограничением оценки.

Закрытие серии не обнуляет историю: её остаток входит в накопленную оценку. Последующее удаление текста из закрытой серии не вычитается. Это сознательная модель приближённого учёта.

Примеры для проверенного обычного поля:

| Действия | Напечатано | После исправлений ≈ | Примечание |
| --- | ---: | ---: | --- |
| abc, Backspace | 3 | 2 | Связанное вероятное удаление |
| abc, Ctrl+V, Backspace | 3 | 3 | Вставка прекращает связь |
| abc, стрелка влево, Backspace | 3 | 3 | После навигации размер не вычитается |
| abc, Ctrl+Backspace | 3 | 3 | Одно действие удаления слова |
| abc, десять Backspace | 3 | 0 | Связанно максимум 3; остальные действия отдельно |
| Ввод IME, отмена композиции | 0 | 0 | Клавиши и отмена учитываются отдельно |

Суточные и минутные суммы должны быть согласованы. Удаление в 12:01 ранее набранного в 12:00 отражается отрицательным net_delta в минуте 12:01. Нельзя обрезать отрицательные минутные дельты: это исказит сумму. net_estimate за произвольный период является изменением оценки за этот период и может быть отрицательным; общий накопленный остаток с начала учёта остаётся неотрицательным. В интерфейсе такой период подписывать «Изменение после исправлений ≈».

## 6. Разбивка по приложениям

Атрибутировать вклад приложению получателю ввода, а не процессу emoji-панели или IME. При клавиатурном событии фиксировать лёгкий снимок HWND, PID/поколения процесса, потока и раскладки либо ссылку на заранее обновлённый контекст. Не определять приложение только после обработки очереди: к тому моменту фокус мог измениться.

Идентификаторы окна, элемента UIA и процесса живут только в памяти. Справочник постоянных приложений в версии 1.0 группирует по executable basename без учёта регистра, например telegram.exe. Несколько процессов одного executable объединяются. Одинаковые basename разных продуктов в этой версии могут объединиться; пользователь может переименовать отображаемую группу, но полного разделения по пути нет.

Постоянные данные приложения: внутренний app_id, exe_name, display_name, пользовательская категория, first_seen_utc, last_seen_utc. Путь к executable используется только временно для метаданных/иконки и не записывается. При недоступном процессе использовать группу «Не удалось определить приложение».

Браузеры группируются по executable, без детализации сайтов и вкладок. Terminal/remote-client группируются по executable получателя; определение вложенной консольной программы не входит в версию 1.0.

## 8. Интерфейс

Язык интерфейса первой версии — русский. Шрифты системные, DPI 100/125/150/200%, доступность с клавиатуры, обычное окно примерно 1000×700 с изменяемым размером. Системная тема, минимальная ширина 800; не использовать WebView или встроенный браузер для графиков.

### 8.1. Трей

Левый щелчок — открыть/активировать окно. Контекстное меню: открыть статистику, пауза/продолжить, сохранить сейчас, настройки, выход. Закрытие окна крестиком скрывает его; выход завершает сбор и выполняет flush.

Tooltip: «Сегодня: 12 340 символов; оценка после исправлений: 11 870; учёт работает». Если есть неизвестный ввод или ошибка сохранения, показывать краткое состояние вместо обещания полноты.

### 8.2. Сводка

Карточки: напечатано; после исправлений ≈; активное время; символов в минуту. Под объёмом показывать разделение «по результату / оценено». Ниже — график по часам и пять приложений с наибольшим объёмом.

При отсутствии активности отображать «Нет данных». При потере измерения отображать пропуск/предупреждение качества, а не непрерывную линию нулей. Обновление текущих значений максимум раз в секунду при открытом окне.

### 8.3. История и приложения

Выбор периода: сегодня, вчера, 7 дней, 30 дней, всё время, произвольные даты. Группировка графика: час/день/неделя. В приложениях колонки: название, напечатано, после исправлений ≈, Backspace/Delete, активное время, скорость, доля оценённых данных. Категории назначаются вручную: работа, общение, код, прочее.

### 8.4. Качество

Показать текущую способность определения поля, композиции и источника ввода; число неизвестных событий; потерянные события; проблемы хранилища; результаты совместимости с датой, версией executable/ОС/IME. Отсутствие клавиатурной активности не называть неисправностью hook: надёжно определить его молчаливое отключение только по отсутствию событий нельзя.

### 8.5. Настройки

Автозапуск выключен по умолчанию. Горячая клавиша паузы по умолчанию Ctrl+Alt+F12, изменение разрешено; при конфликте показать ошибку регистрации и оставить команду трея работоспособной. Настраиваемые параметры: idle gap 5 секунд (диапазон 1–30), перерыв между сессиями 60 секунд (30–600), хранение минутных данных, дневная цель, папка экспорта.

Не предлагать настройки списка исключений и записи текста.

## 9. Аналитика и формулы

### 9.1. Обязательная аналитика

- Тепловая карта «день недели × час»: объём и отдельно активное время.
- Дневной тренд: символы, 7-дневное скользящее среднее, сравнение одинаковых периодов. Неполный текущий день сравнивать с тем же временным срезом либо подписывать как неполный.
- Доли приложений и пользовательских категорий по объёму.
- Действия исправления: Backspace, Delete, удаления слов, Undo/Redo; не называть это процентом ошибок.
- Раскладки / профили ввода: объём и количество переключений; не определять язык по содержимому.
- Качество: доля estimated среди посчитанных символов плюс отдельный счётчик unresolved. Смешение источников видно во всех сводках.

### 9.2. Активное время

Для принятых текстовых событий в одном контексте строить интервалы [t, t + idle_gap], по умолчанию 5 секунд. Пересекающиеся интервалы объединять. Конец ограничивается сменой приложения, паузой, блокировкой, сном или завершением учёта. Текущий незавершённый интервал ограничивается текущим временем.

Физические команды без текстового вклада и неизвестные события не добавляют активное время печати. Длительность подготовки IME не считать скоростью сформированных символов; при необходимости отдельно выводить «время работы с клавиатурой» на следующем этапе.

Длительности измерять монотонными часами. Пересекающиеся интервалы нескольких приложений не суммировать дважды; контекст при смене фокуса закрывается. Одиночный символ может дать до 5 секунд активного времени; это определение метрики, а не измерение времени движения пальца.

CPM = gross_total / (active_typing_ms / 60000). При активном времени меньше 30 секунд показывать «мало данных» вместо устойчивой средней. Порог сохраняется в metadata экспорта.

### 9.3. Сессии

Начало — первый принятый текстовый вклад. Завершение — перерыв более session_gap, ручная пауза, блокировка, сон или выход. Смена приложения закрывает серию исправлений, но сама по себе не заканчивает общую сессию. Хранить агрегат сессии и агрегаты по приложениям внутри неё.

Сессии показывают длительность от первого до последнего события, активное время и объём. Между этими длительностями не ставить знак равенства.

### 9.4. Полезные расширения после стабильной версии

1. Дневная цель и ненавязчивое уведомление один раз при достижении; цель по умолчанию выключена.
2. Личные рекорды: день, час, объём сессии. Рекорды скорости учитывать только для окон с достаточной активностью и известным качеством данных.
3. Распределение скорости: медиана/P90 по активным минутам; не усреднять средние без весов.
4. Календарь активности и серии дней с выполненной целью.
5. Поиск привычных часов интенсивного набора при накоплении минимум 14 дней; это описание активности, а не вывод о продуктивности.
6. Сравнение коротких/длинных сессий и частоты действий исправления.
7. Ручные метки «проект» и «задача» для текущей сессии без чтения названий документов.
8. Переключения приложений во время набора: хранить суммы по временным корзинам, не историю всех посещённых окон.
9. Напоминания о перерывах на основе длительности сессии, с выключенным по умолчанию звуком.
10. WPM как условная величина CPM/5 с явной подписью «условные слова». Не выдавать её за фактическое количество слов на любом языке.

Частоты букв, наиболее частые слова, клавиатурная тепловая карта и точное число слов не включены в 1.0: они требуют другой модели собираемых данных. Новые показатели не должны незаметно добавлять сохранение текста или последовательностей клавиш.

## 10. Технологии и структура

Основной стек: C#, .NET 10 LTS, WinForms, Win32 P/Invoke, UI Automation COM, SQLite через Microsoft.Data.Sqlite без тяжёлого ORM. Основной тестовый target — поддерживаемая Windows 11 x64 на компьютере пользователя. Windows 10 — дополнительная совместимость только после отдельной проверки конкретной редакции и сборки; не объявлять её автоматически официально поддерживаемой выбранным runtime.

Поставлять ZIP framework-dependent сборки. На компьютере требуется .NET Desktop Runtime выбранной основной версии. Дополнительный self-contained ZIP возможен позже, его размер измерять отдельно. Portable означает запуск без установщика; место данных регулируется отдельно.

Структура solution:

- TypingStats.App — host, трей, WinForms, запуск/выход.
- TypingStats.Core — правила подсчёта, состояния, аналитика без зависимости от Win32.
- TypingStats.Windows — hook, контекст окна, UIA, классификация источников.
- TypingStats.Storage — SQLite, запросы, миграции, backup/export.
- TypingStats.Tests — логические тесты и интеграционные сценарии.
- TypingStats.TestHost — контролируемые поля для проверки ввода; не часть пользовательской поставки.

Логические сервисы внутри проектов: KeyboardCapture, ForegroundContextTracker, LayoutInterpreter, CompositionObserver, InputCorrelator, GraphemeCounter, EditEstimateTracker, SessionTracker, StatisticsAggregator, Repository, QueryService. Не создавать отдельный процесс или проект для каждого класса.

## 11. Потоки и технические ограничения

### 11.1. Keyboard capture

WH_KEYBOARD_LL на выделенном потоке с message loop. Callback сохраняет только необходимые поля и лёгкий снимок контекста, обновляет состояние клавиш и делает TryWrite в bounded-очередь. Запрещены обращения к SQLite, чтение executable, COM/UIA, блокирующие lock и ожидания worker.

Всегда передавать события дальше через CallNextHookEx; ничего не блокировать и не подменять. Собственное состояние модификаторов обновлять по keydown/keyup с инициализацией и повторной синхронизацией при восстановлении контекста. GetAsyncKeyState внутри callback не является достоверным состоянием нового события.

Ёмкость очереди raw keyboard metadata: 8192. При переполнении не блокировать callback; увеличить lost_events, прервать серии и композиционную корреляцию, синхронизировать состояние клавиш. Клавиши и их последовательность доступны в очереди лишь временно, не журналируются и не переносятся в постоянное хранилище.

### 11.2. Раскладка и Unicode

Сохранять раскладку потока получателя в момент ввода. Не брать раскладку потока интерфейса утилиты. ToUnicodeEx вызывать в режиме без изменения состояния клавиатурного буфера. Этот флаг предотвращает вмешательство в ввод, но сам по себе не реализует правильную обработку dead keys: нужный интерпретатор должен быть проверен отдельно.

При невозможности безопасно воспроизвести состояние dead key/AltGr/Alt+numpad не выдавать выдуманную букву. Доступный итог композиции имеет приоритет; иначе соответствующий случай Unresolved.

Сегментация графем потоковая. Допустим временный изменяемый буфер последней незавершённой графемы максимум 256 UTF-16 units на активный контекст. Не хранить полный набранный фрагмент. При переполнении или разрыве контекста пометить неоднозначную границу, очистить состояние и продолжить с новой серией. Граница графемы может пересекать события и минуту; корректировка относится к первоначальному вкладу и применяется идемпотентно.

### 11.3. UI Automation

Выделенный MTA-поток для создания COM-объектов, определения активного элемента и изменения подписок. Не выполнять UIA-вызовы из WinForms-потока. Подписываться на активный элемент/нужное поддерево, не сканировать непрерывно весь desktop. Подписки и отписки последовательны; устаревшие элементы обрабатываются как смена/потеря контекста.

Composition/CompositionFinalized обрабатывать с учётом контракта провайдера. Промежуточная композиция не прибавляет символы. Пустая финализация — отмена/удаление, вклад 0. AutoCorrect/AutoComplete не прибавляют ручной объём. Общее TextChanged без размера и происхождения используется только как сигнал возможной потери связи.

Не вызывать DocumentRange.GetText или ValuePattern.Value ради сравнения всего документа. Обработчик полученного композиционного текста преобразует его в числовой результат и ограниченное состояние графем. Полный payload не пересылается в общую очередь и не сохраняется. Ограничение обработки одного payload — 4096 UTF-16 units; превышение означает Unresolved, а не молчаливое усечение и прибавление неполного числа.

Корреляция выполняется по порядку контекста, source generation и идентификатору композиции. Внутри входного адаптера разрешена краткая синхронизация состояния; callback hook её не ожидает. Операции с COM и БД не выполняются под этой синхронизацией.

Нельзя гарантировать мгновенное стирание всех строк, созданных системой/COM/.NET. Собственные изменяемые буферы очищать после использования, срок жизни заимствованных строк минимизировать. Гарантия продукта относится к отсутствию постоянной записи текста.

## 12. Коррелятор и профили совместимости

Состояния: Ordinary, CompositionActive, Finalized, Cancelled, ContextLost. Профиль задаёт возможности сценария, а не общий рейтинг executable: допустимость клавиатурной оценки, наличие finalization, различимость paste, политика Enter/Tab, правила software keyboard.

До окончания этапа проверки все профили имеют статус unverified. Статус tested задаётся только по фактическому отчёту с версиями приложения, ОС и IME. Изменение существенной версии приложения/IME снижает профиль до unverified до повторного теста. Сценарий может быть partial или unsupported; такой результат не означает запрет наблюдения клавиш.

Алгоритм:

1. Присвоить контексту поколение; события старого поколения не относить новому приложению.
2. При обычном вводе разрешённая трансляция даёт KeyEstimated.
3. Для IME-профиля промежуточные клавиши удерживаются как числовой provisional-вклад без публикации текста. Если нельзя отделить начало композиции, не считать буквы подготовки как конечные символы.
4. При финализации с установленным происхождением заменить provisional-вклад на длину результата, ровно один раз. Числовые корректировки допустимы; подтверждённый результат и подготовка не суммируются.
5. При отмене вклад в текст 0; действие отмены и клавиатурная активность остаются в отдельных агрегатах.
6. При ContextLost незавершённую композицию перевести в unresolved. Не считать отсутствие finalization завершением.
7. На границе UTC-минуты сохранять только числовое provisional-состояние и состояние контекста в RAM. После crash не восстанавливать неизвестную композицию как завершённую.
8. Для запоздалого результата сохранить tombstone контекста в RAM до 2 секунд с числовыми идентификаторами. Позднее событие не привязывать к текущему окну. Если контекст уже неизвестен — unresolved. Таймаут не является подтверждением происхождения.
9. Дедупликация использует переходы состояния и профиль провайдера, а не совпадение содержимого строк. Две одинаковые введённые композиции подряд должны давать два вклада.

Коррелятор гарантирует отсутствие двойного подсчёта на принятых тестовых сценариях. Универсальная дедупликация любых нестандартных провайдеров не объявляется.

## 13. Локальная модель данных

Хранилище по умолчанию: %LOCALAPPDATA%/TypingStats/. Файл settings.json содержит только настройки. stats.sqlite — агрегаты. portable.flag рядом с executable включает хранение в ./data/, если каталог доступен для записи. Смешивать базы двух режимов автоматически нельзя.

Числовые счётчики — 64-bit integer. Время — UTC timestamp, дополнительно записывать локальную дату, UTC offset и идентификатор часового пояса на момент измерения. Для длительности использовать monotonic clock.

### 13.2. Периоды, хранение и корректировки

Минутные корзины: 90 дней по умолчанию. Часовые: 2 года. Дневные: бессрочно. Сессии и session_apps: 2 года. Пользователь может уменьшить срок или хранить минутные данные бессрочно. Детализация старого периода в UI ограничивается сохранённым разрешением.

Укрупнение данных — атомарная транзакция: сформировать суммы, проверить отсутствие повторного учёта, затем удалить исходные корзины. Запрос выбирает непересекающиеся разрешения; минутные, часовые и дневные копии нельзя суммировать вместе.

Запоздалые числовые поправки обновляют существующие более крупные агрегаты в той же транзакции. Ограничение нуля применяется только к остатку связанной серии, не к каждой временной корзине.

Локальная дата события сохраняется на момент ввода. После поездки старый день не переносится автоматически в другой часовой пояс. Повторяющиеся часы перехода времени различаются offset; UTC-порядок сохраняется. Смена timezone закрывает временную корзину и начинает новую.

## 14. Сохранение, сбои и восстановление

Flush каждые 5 секунд и при паузе, выходе, уведомлении о сне/завершении сессии ОС. Один writer, транзакции SQLite, WAL, foreign_keys=ON. Использовать FULL synchronous для цели сохранности подтверждённых транзакций; производительность проверить на целевом компьютере.

Агрегаты передавать на запись со стабильным batch_id. Повтор записи после неизвестного результата транзакции не должен удваивать показатели. При ошибке хранения оставлять неприменённые суммы в RAM; не удалять их до подтверждения commit.

Цель при штатно работающем хранилище: при crash потерять не более последнего интервала flush плюс незавершённые provisional-результаты. Это не гарантия при аппаратной неисправности, зависшем диске или невозможности записи. Очередь flush не должна бесконечно удерживать raw-события.

При disk full/lock показывать «Статистика ещё не сохранена», ограничить накопление агрегатов в RAM 16 МБ. Повторять запись с паузами 1, 2, 5, затем 30 секунд. При достижении лимита переходить в состояние «учёт остановлен: хранилище», предварительно сохранив доступные агрегаты в RAM и сообщив о проблеме. Не сообщать, что база содержит всё.

После неправильного завершения проверить базу через quick_check. При повреждении сохранить исходную базу и предложить восстановление из backup. Не заменять её пустой автоматически.

Backup через согласованный SQLite backup API; не копировать открытый main-файл без учёта WAL. Автоматически создавать до одной резервной копии в день при наличии новых данных, хранить последние 7. Перед миграцией создавать дополнительный backup. Восстановление выполняется при остановленном collector и закрытых соединениях, с подтверждением пользователя.

## 15. Экспорт и операции с историей

CSV UTF-8 с BOM, стабильные английские имена колонок, invariant numeric format, UTC ISO timestamps. Мастер выбора: период, разрешение, приложения, файл. Не смешивать CSV-разделитель с локальным десятичным разделителем; все значения, содержащие separator, кавычки или перевод строки, экранируются. Для пользовательских имён безопасно обрабатывать ведущие формульные символы при открытии CSV в таблицах.

Колонки экспорта: period_start_utc, local_date, offset_minutes, app_name, exe_name, input_profile, gross_observed, gross_estimated, net_delta_estimate, linked_backspace_estimate, deletion_actions, active_typing_ms, unresolved_count, lost_events, metric_definition_version. В поясняющем соседнем JSON фиксировать параметры активного времени, точность и выбранное разрешение.

Удаление истории — отдельная команда с показом точного периода и возможностью backup. Для частичного удаления удалить/пересчитать все связанные разрешения и суммы сессий, чтобы данные не появлялись вновь из старых часовых/дневных копий. Удаление внутри окна с грубой детализацией разрешать только целиком по доступной корзине и показывать фактическую границу.

## 16. Производительность и эксплуатация

Контрольная среда: компьютер пользователя; в benchmark-report записать CPU, RAM, Windows build, runtime, приложения и IME. Все числовые ограничения ниже — критерии, которые требуется измерить, а не уже полученные результаты.

| Показатель | Цель |
| --- | --- |
| CPU в простое, 10 минут, окно закрыто | Среднее ≤0,1% общей вычислительной мощности системы |
| CPU при наборе 10 событий/сек, 10 минут | Среднее ≤1% общей мощности |
| Hook callback | P99 ≤1 мс, без синхронных I/O |
| RAM в фоне через 30 минут | Working set целевой ≤70 МБ; дополнительно измерять private bytes |
| Память в soak-тесте 8 часов | Без неограниченного роста; рост private bytes ≤10 МБ после прогрева при одинаковой нагрузке |
| Открытие окна на базе с 1 годом данных | ≤2 секунд для первого полезного отображения |
| Обычный запрос 30 дней | ≤500 мс на контрольной базе |
| Обновление видимой сводки | Не более 1 раза/сек |
| Размер framework-dependent поставки | Цель ≤25 МБ без установленного runtime и пользовательских данных |

UIA-наблюдение не должно ухудшать отзывчивость набора. Зависшее/недоступное поле переводит адаптер в ограниченный режим; collector keyboard продолжает работать. При необходимости изоляция проблемного COM-адаптера в helper-process — отдельное расширение после измерения, не базовая архитектура.

Приложение запускается без административных прав. Поддержка повышенных процессов и защищённых элементов определяется тестом; при недоступности не повышать свои права автоматически. В 1.0 нет драйвера, внедрения DLL в целевые процессы и изменения активного IME.

Один экземпляр на пользователя/сессию, второй запуск активирует окно. Автозапуск создаётся только явным включением настройки. При отсутствии runtime вывод/документация должны объяснять конкретную зависимость.

## 17. Проверка совместимости до основного интерфейса

Этап 0 — самостоятельный обязательный результат: минимальный collector, контролируемый TestHost и отчёт compatibility-report.md. В пользовательском приложении текстовые логи не включать; TestHost знает ожидаемые результаты собственных заранее заданных примеров.

Сценарии проверять в обычном поле TestHost и в доступных приложениях пользователя. Стартовая матрица: Блокнот, браузерный textarea/input/contenteditable, Telegram, VS Code, Windows Terminal; Word — при наличии. Это список тестов, а не утверждение поддержки. Зафиксировать версии.

Способы ввода: RU/EN, раскладка с AltGr и dead keys, японский/китайский IME при наличии, emoji-панель, обычная и сенсорная экранные клавиатуры при наличии. Не считать непроведённый тест успешным. Для отсутствующего IME допустим статус not_tested с причиной, но соответствующая возможность не включается в гарантированную приёмку.

Условие перехода: для обычного набора в основных ежедневных приложениях нет необъяснённых расхождений; для сложного ввода известны работающие и ограниченные сценарии; есть проверенный способ подавления дублей и paste. Если условие не выполнено, сначала исправить адаптер или зафиксировать ограничение в UI/ТЗ. Не продолжать интерфейс с обещанием универсальной точности.

## 18. Тесты и критерии приёмки

### 18.1. Логические тесты Core

Проверить сегментацию Unicode и перенос незавершённой графемы через границы событий; keydown/keyup/repeat; AltGr; комбинации команд; состояние композиции; повторяющиеся одинаковые результаты; отмену; смену контекста; поздние события; net estimate; периоды и отрицательные net_delta; идемпотентные batch; UTC/local date; длительности и интервалы активности.

Тесты не должны просто повторять реализацию. Нужны конкретные независимые ожидаемые результаты, в том числе генерация разных разбиений одного и того же Unicode-примера на события.

| --- | --- | --- |

### 18.3. Итоговая приёмка

Обязательны: функции F01–F14, выполненная матрица обычных сценариев, прошедшие логические тесты, проверка хранилища и отсутствие постоянной записи текста. Для основных заявленных сочетаний «приложение + профиль ввода» — нулевое расхождение на принятом наборе тестов и отсутствие дублей.

Должны быть представлены результаты benchmark и soak-теста. Если ресурсная цель не достигнута, фактическое значение и причина фиксируются до объявления релиза. Проверенный набор сценариев не переносится автоматически на все приложения/языки.

## 19. План реализации и зависимости

| Этап | Работы | Передаваемый результат |
| --- | --- | --- |
| 0. Исследование ввода | Collector, TestHost, hook/UIA, профили, матрица IME/emoji/paste | Прототип и compatibility-report; решение о границах покрытия |
| 1. Ядро | Модель событий, потоковые графемы, состояния композиции, net estimate, сессии | Core с независимыми тестами и документом правил |
| 2. Windows-адаптер | Контекст, источники, thread model, bounded queue, жизненный цикл | Рабочий фоновый гибрид на принятых сценариях |
| 3. Хранение | Schema/migrations, batch id, агрегаты, backup, ошибки | Проверенная SQLite-база и восстановление |
| 4. Продуктовый интерфейс | Трей, сводка, история, приложения, качество, настройки, CSV | Используемая персональная версия без расширенной аналитики |
| 5. Аналитика | Heatmap, CPM, сессии, раскладки, сравнение периодов | Основная статистика с объяснёнными формулами |
| 6. Стабилизация | Soak, CPU/RAM, DPI, crash/disk full, упаковка | ZIP, отчёты и инструкция |

Этапы 1 и 2 используют результаты этапа 0; UI не должен определять алгоритм учёта. Оценку трудозатрат уточнять после этапа 0. Особенно неопределённы охват сложного ввода и происхождение software input; не обещать срок универсального решения до проверки.

После релиза 1.0 отдельно выбирать расширения из раздела 9.4. Не добавлять TSF-службу или plugin каждого редактора без отдельного решения: это существенно меняет сложность и способ установки.

## 20. Комплект результата

Разработчик передаёт:
