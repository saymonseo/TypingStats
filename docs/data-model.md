# Данные версии 0.1

stats.sqlite, schema_version=1:

- metrics: UTC bucket, resolution (0=min, 1=hour, 2=day), сохранённая локальная дата/час/offset/zone, executable, input profile, отдельные 64-bit counters.
- batches: стабильный batch id и время commit для идемпотентных повторов.
- sessions: агрегаты завершённых сессий (start/end/gross/active/reason).
- applications: executable и ручная категория.

Каждый числовой вклад одной транзакцией обновляет минутный, часовой и дневной уровень. QueryService/UI читает ровно один уровень, чтобы не складывать копии. Подтверждённые транзакции защищены FULL synchronous/WAL. Backup использует SQLite BackupDatabase, а не копирование открытого main-файла.

Net не хранится как независимое значение: Observed + Estimated − LinkedBackspaces. Корзины могут иметь отрицательный net. Потерянные и unresolved события не преобразуются в количество символов.

Реальная модель первого релиза компактнее полного проектного ТЗ: отдельные session_apps, collector_runs и постоянные compatibility profiles пока не создаются. Совместимость описана в отчёте, а данные качества видны в интерфейсе.

В базе нет символов, clipboard, заголовков окон, путей документов, HWND, PID и key sequences. Временные идентификаторы полей живут только в RAM. pending-aggregates.json при ошибке сохранения содержит только сериализованные числовые batch и контекст агрегатов; при следующем старте импорт идемпотентен.

Миграция более новой неизвестной схемы запрещена: приложение сообщает об ошибке и сохраняет исходный файл. Перед восстановлением и удалением история копируется.
